# FleetGuard CDK Infrastructure

TypeScript CDK project provisioning all AWS resources for the FleetGuard multi-tenant SaaS fleet intelligence platform.

## Prerequisites

```bash
pnpm install -g aws-cdk
pnpm install
pnpm run build

# Bootstrap CDK in your account (one-time per account/region)
cdk bootstrap aws://ACCOUNT_ID/af-south-1
```

## Deploy Order

Stacks must be deployed in dependency order. The `deploy:all` script handles this:

```bash
# Full deploy (resolves dependency order automatically)
cdk deploy --all --require-approval never -c stage=prod

# Or individual stacks
pnpm run deploy:foundation   # VPC, SGs, ECR repos
pnpm run deploy:data         # RDS Aurora, ElastiCache Redis
pnpm run deploy:iot          # IoT Core rules, SQS, SNS, S3
pnpm run deploy:compute      # ECS Fargate services, ALB, API GW, CloudFront
```

## Staging Environment

```bash
cdk deploy --all -c stage=staging
```

Staging differences from prod:
- Aurora Serverless v2 max ACU: 4 (vs 16)
- No Aurora read replica
- 1 NAT Gateway (same as prod — already cost-optimised)
- Fargate desired count: 1 per service (vs 2)
- Log retention: 1 week (vs 1 month)
- S3 auto-delete on stack destroy

## Stack Map

```
FleetGuard-Foundation
  └── VPC (2 AZs, 1 NAT GW)
  └── Security Groups (ECS, RDS, Redis)
  └── ECR Repositories (8 services)

FleetGuard-Data
  └── Aurora PostgreSQL Serverless v2 (PostGIS + TimescaleDB via init SQL)
  └── ElastiCache Redis Serverless

FleetGuard-IoT
  └── AWS IoT Core (rules engine → SQS)
  └── SQS: telemetry-ingest, alert-processing, ai-inference (each with DLQ)
  └── SNS: critical-alerts
  └── S3: raw-logs (lifecycle to Glacier), firmware, reports

FleetGuard-Compute
  └── ECS Fargate Cluster (Container Insights in prod)
  └── Internal ALB
  └── Services: api-gateway, auth, websocket (on-demand)
  └── Services: telemetry-ingest, alert-processing, ai-inference,
               route-sync, reporting (Spot + on-demand fallback)
  └── API Gateway HTTP API → ALB
  └── CloudFront Distribution (PRICE_CLASS_ALL for African PoPs)
```

## Post-Deploy: Database Init

After first deploy, run the init SQL to enable extensions:

```sql
-- Connect to Aurora cluster writer endpoint
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS timescaledb;
CREATE EXTENSION IF NOT EXISTS pg_stat_statements;

-- Convert GPS and fuel event tables to hypertables (run after table creation)
SELECT create_hypertable('gps_events', 'ts', chunk_time_interval => INTERVAL '1 week');
SELECT create_hypertable('fuel_events', 'ts', chunk_time_interval => INTERVAL '1 week');

-- Row-level security
ALTER TABLE vehicles ENABLE ROW LEVEL SECURITY;
-- Repeat for all tenant-scoped tables. See db/rls.sql in the app repo.
```

## OBU Device Provisioning

After `FleetGuard-IoT` deploys:

1. Get the IoT endpoint: `aws iot describe-endpoint --endpoint-type iot:Data-ATS`
2. Create a device certificate per OBU: `aws iot create-keys-and-certificate --set-as-active`
3. Attach IoT policy allowing `iot:Connect`, `iot:Publish` on `fg/{tenant_id}/{vehicle_id}/*`
4. Flash cert + key onto OBU SD card during manufacture

For scale (>50 OBUs), switch to IoT Just-in-Time Provisioning (JITP) with a CA certificate.

- ECS: add replicas as needed
- Estimated total: **~$500–700/mo** before revenue offset

## Environment Variables Required in Secrets Manager

The following secrets must be created manually before first deploy
(or added to the CDK via `new Secret()` with `generateSecretString`):

- `fleetguard/{stage}/jwt-secret` — RS256 private key for JWT signing
- `fleetguard/{stage}/stripe-key` — Stripe secret key (or Paystack)
- `fleetguard/{stage}/mapbox-token` — Mapbox GL JS server token

RDS credentials are auto-generated by CDK and stored in Secrets Manager.
